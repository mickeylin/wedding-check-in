# 接待介面審視與調整

2026-11-14 更新。審視範圍涵蓋登入、掃碼、編號查詢、姓名查詢、一般紅包收件、例外收件及婚宴後清點。

## 接待流程

主畫面依序提供工作人員登入、掃 QR／輸入編號、姓名與分類查詢、需要處理的同步紀錄、其他紅包收件，以及婚宴後使用。

「其他紅包收件」預設收合，展開後可登記名單外或代送紅包。「婚宴後使用」展開後可進入紅包清單。切換到清點時，掃描、查詢與其他收件入口會收起。

名單外／代收紅包使用獨立表單，只由主畫面入口開啟。新登記的 E 編號紅包以署名記錄，賓客頁只提供本人收件、撤銷與同行備註。既有的 E 編號即使曾關聯賓客，也排除於本人收件狀態及防重複收件判斷之外。

## 發現與修正

| 問題 | 調整 |
| --- | --- |
| 掃碼後仍用「下一位」表示離開賓客畫面 | 改為「返回掃描」。姓名查詢使用「返回查詢結果」，輸入編號使用「返回編號查詢」 |
| 例外紅包入口位於主要查詢功能前面 | 移到查詢及同步紀錄下方，收在「其他紅包收件」 |
| 返回按鈕位於詳情前面，捲動後位置不明確 | 改放在賓客卡底部，長內容捲動時仍可操作 |
| 查詢結果的按鈕重複寫出分類與紅包資訊 | 使用「查看賓客」，保留姓名和分類供辨認 |
| 初始分類選項沿用舊名單 | 登入後從實際名單建立分類選項 |
| 頁首同步狀態可能連到隱藏區塊 | 有同步待辦時展開紀錄，其他情況開啟工作人員登入 |
| 登入欄位未填寫時，使用者要自行尋找缺漏 | 開啟登入區並聚焦姓名或 PIN 欄位 |
| 賓客頁也可登記代收，並帶入當前賓客編號 | 例外表單改由獨立入口開啟，新收件只記署名及 E 編號 |
| 例外收件成功後仍可連按登記，可能新增同一包 | 顯示成功提示與 E 編號，鎖定這次輸入並收合表單 |
| 返回時直接丟掉尚未登記的署名或備註 | 詢問是否放棄輸入。已保留的待核對操作可在主畫面重試 |
| 代收紀錄影響本人收件狀態，或上一包提示殘留 | E 編號紅包獨立於本人收件判斷，離開後清除代收提示 |
| 小螢幕的長分類名稱及清點按鈕過度換行 | 調整分類字級與手機清點按鈕排列 |

一般收件先保存在手機，再背景同步。卡片以文字區分「已保存在這支手機・待同步」與「已登記收紅包」。查詢與返回沿用同一張賓客卡，姓名查詢返回後保留原搜尋結果和選取位置。

## 驗證

- 自動測試涵蓋掃碼返回、查詢失敗返回、背景同步、例外收件防重複、E 編號保留、草稿放棄確認與清點返回。
- 重現「只有一筆代收 E 紅包卻顯示本人已收」後，驗證賓客查詢、登入快照、本人收件與撤銷。瀏覽器另驗證先代收再掃本人 QR 時仍可收下本人的紅包，展開賓客詳情也沒有代收表單。
- 使用獨立背景瀏覽器和合成資料，驗證 320、390、1024 像素寬度下的登入、掃碼回呼、一般收件、姓名查詢返回、例外收件、清點清單與編輯頁。
- 逐一檢視上述寬度的畫面截圖，確認主要按鈕、長姓名、長分類、成功訊息與返回位置。未出現水平溢出或頁面執行錯誤。

瀏覽器驗證使用模擬相機回呼及 API 回應。實際手機的相機權限、掃碼辨識及螢幕鍵盤仍需實機操作確認。
